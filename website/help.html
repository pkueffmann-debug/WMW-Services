01Voice-Mode

JARVIS hört nicht permanent mit. Du musst Voice aktiv einschalten — dann läuft eine Voice-Loop, die jede Pause als „fertig gesprochen" interpretiert.

Aktion
So gehts
Voice einschalten
Oben rechts auf ◉ ENABLE VOICE tippen. Beim ersten Mal Browser-Mikrofon-Berechtigung erlauben. Der Button pulsiert cyan während er hört.
Voice ausschalten
Selber Button (jetzt ◉ VOICE ON) → ausschalten. Browser-Mic-Indikator verschwindet.
JARVIS unterbrechen
Während er spricht: offene Hand zeigen (Hand-Tracking an) oder einfach kurz lautes Sprechen — die VAD springt an wenn er zu Ende ist.
Ultra-Mode
Pille ◌ ULTRA MODE aktiviert „Debate": 3 KI-Modelle (Claude + GPT + Gemini) antworten parallel, Synthese als finale Antwort. Langsamer, dafür durchdachter.
Cooldown: Nach jeder Antwort wartet JARVIS 1,5 s bevor er wieder zuhört — sonst würde sein eigenes TTS-Echo die nächste Aufnahme triggern.

04Mac-Tools (Desktop-App)

Wenn die JARVIS Desktop-App läuft, verbindet sie sich über einen lokalen WebSocket (Port 7777). Das Badge oben rechts wird grün und JARVIS bekommt Zugriff auf deinen Mac.

Tool
Beispiel-Frage
App öffnen
„Öffne Spotify / Mail / Calendar / Slack"
URL / Datei öffnen
„Öffne github.com" · „Öffne ~/Downloads/report.pdf"
Shell-Befehl
„Wie ist meine Uptime?" → uptime. Gefährliche Commands (rm, sudo, network) werden serverseitig refused.
Screenshot
„Mach einen Screenshot" → PNG erscheint inline im Chat.
Clipboard lesen / schreiben
„Was hab ich kopiert?" · „Kopier 'foo' in die Zwischenablage"
Sicher: Der WebSocket bindet ausschließlich auf 127.0.0.1. Niemand außerhalb deines Macs kann darauf zugreifen. Befehle gehen durch eine Action-Whitelist + Shell-Sicherheitsfilter.

07Morgen-Briefing

Einmal pro Tag zwischen 8:00 und 11:00 Uhr Lokalzeit liest JARVIS automatisch die News vor — sobald du /brain in dem Zeitfenster offen hast.

Mechanik
Details
Wann?
8:00-11:00 lokale Zeit, einmal pro Kalendertag.
Wie gemerkt?
localStorage.jarvisLastBriefedDate mit dem ISO-Datum.
Sofort testen
URL /brain?briefing=test erzwingt das Briefing unabhängig von Uhrzeit / Tag.
„Mehr dazu"
Funktioniert über Voice oder Chat — das volle Briefing liegt in der Chat-History, Claude kann auf einzelne Punkte eingehen.

09Probleme lösen

Symptom
Was tun
JARVIS antwortet nicht
DevTools-Konsole öffnen (Cmd+Opt+I). „[askJarvis]"-Logs zeigen warum. Wenn Server-5xx: nochmal probieren — der Client hat Auto-Retry mit Timeout.
Voice hört nichts
Browser-Mic-Permission checken (Schloss-Symbol in der Adressleiste). VAD-Threshold ist 0.025 RMS — bei sehr leisem Mic ggf. lauter ins Mikrofon.
Falscher Code im Briefing („thank you" o.ä.)
Whisper-Halluzination bei stillen Aufnahmen. Wird durch confidence- und length-checks rausgefiltert; falls's trotzdem durchrutscht → Confidence-Schwelle in brain.html hochziehen.
Desktop-Badge bleibt grau
Desktop-App nicht gestartet, oder der lokale Port 7777 ist von etwas anderem belegt. lsof -i :7777 zeigt den Konflikt.
Hand-Tracking lädt nicht
CDN-Block (Adblocker / Firmen-Proxy)? MediaPipe-Assets kommen von cdn.jsdelivr.net — die musst du im Adblocker erlauben.
Account-Probleme: Falls JARVIS dich auf /auth.html wirft obwohl du eingeloggt bist — Cookie löschen (sb-access-token) und neu via OTP einloggen.
